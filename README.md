# Visual Director

An Agent Skill that helps AI coding agents audit and guide a frontend's visual consistency against **your project's own design system**: design tokens, color and contrast, typography, spacing, buttons and component variants, icons, responsive layout, dark/light themes, accessibility basics, reduced motion and visual regressions.

It is a methodology written for agents (a `SKILL.md` plus reference checklists), not an automated scanner. The agent uses the tools your project already has and reports findings backed by evidence.

## What it is for

Use it when you want a careful, evidence-based visual review, for example:

- **AI-generated UI drifting from your design system.** An agent produced a component with hard-coded colors, an off-scale font size and a locally styled button. The skill guides the agent to find the drift and propose the smallest fix using your existing tokens and components.
- **Reviewing a pull request for visual consistency.** Focus on the diff, separate new regressions from existing debt, and cite `file:line` evidence.
- **A visual QA pass before a release.** Check critical pages across themes and viewports, with honest coverage: what ran, what was skipped and why.
- **Auditing dark and light mode.** Find surfaces that don't switch with the theme, tokens missing in one theme and text below WCAG AA contrast.

It helps frontend developers, design-system maintainers, designers who review implementations, and teams that let AI agents write UI.

## How it works

1. **Find the source of truth:** tokens, theme files, `DESIGN.md`, the component library and existing patterns.
2. **Scope:** routes, components, themes, viewports and states.
3. **Inspect read-only:** static search, your linters and tests, and the running app if a browser tool is available.
4. **Report:** verified defects, items that need review and subjective suggestions in separate groups, plus a coverage table.
5. **Fix only with approval:** the smallest change, the same checks re-run, before/after evidence.

The agent never reports a check as passed unless it ran it, and never sends screenshots or code to third-party services without your consent.

## Install

Copy the `skills/visual-director` folder into the skills directory your agent reads:

| Agent | Destination |
|---|---|
| Claude Code | `.claude/skills/visual-director/` in your project, or `~/.claude/skills/visual-director/` for all projects |
| Codex | `.agents/skills/visual-director/` in your project |
| Kiro | `.kiro/skills/visual-director/` in your project |
| Cursor or any agent that reads `SKILL.md` | the skills folder that agent loads (see its documentation) |

For example, for Claude Code, from your project root:

```bash
git clone --depth 1 https://github.com/Starbots-devv/visual-director.git /tmp/visual-director
mkdir -p .claude/skills
cp -r /tmp/visual-director/skills/visual-director .claude/skills/
```

**Or download the zip.** [`dist/visual-director.zip`](dist/visual-director.zip) contains a single `visual-director/` folder. Unzip it into one of the destinations above, or upload it to an app that installs skills from a ZIP file.

The agent loads the skill when a request matches its description. You can also ask for it by name.

## Limits

- It is a methodology for agents, not an automated scanner or CI gate. Results depend on the agent, the model and the tools available in your environment.
- Runtime checks (computed styles, screenshots, viewport behavior, reduced motion) need a running app and a browser tool. Without them, those checks are reported as `NOT_RUN`.
- It checks against your rules. If the project has no tokens or design documentation, the agent can only infer rules from existing usage and will ask you to confirm them.
- Accessibility coverage is basic. It does not replace a full WCAG audit or testing with assistive technologies.
- Screenshot diffs show that something changed, not whether it is better. Design judgment stays with people.

## Resumen en español

**Visual Director** es un Agent Skill para agentes de IA de programación (Claude Code, Codex, Kiro, Cursor y cualquier agente que lea `SKILL.md`). Guía al agente para auditar la coherencia visual de un frontend contra **el propio design system del proyecto**: tokens frente a valores escritos a mano, color y contraste, tipografía, espaciado, botones y variantes de componentes, iconos, layout responsive, temas oscuro y claro, accesibilidad básica, movimiento reducido y regresiones visuales.

**Para qué sirve:**

- Detectar cuándo una UI generada por IA se aparta del design system y proponer la corrección mínima con los tokens y componentes existentes.
- Revisar un pull request por coherencia visual, separando regresiones nuevas de deuda previa.
- Preparar un pase de QA visual antes de un lanzamiento, con cobertura honesta.
- Auditar los modos oscuro y claro.

**Cómo trabaja:** primero en solo lectura y con evidencia (código, DOM, capturas); separa defectos verificados de sugerencias subjetivas; nunca da por superada una comprobación que no se ejecutó; no envía capturas con datos personales a terceros sin consentimiento; solo aplica cambios con aprobación.

**Instalación:** copia `skills/visual-director` en `.claude/skills/` (Claude Code), `.agents/skills/` (Codex), `.kiro/skills/` (Kiro) o en la carpeta de skills de tu agente; o descarga `dist/visual-director.zip`.

**Límites:** es una metodología para agentes, no un escáner automático. Las comprobaciones en navegador requieren la app en marcha y una herramienta de navegador; lo que no se puede ejecutar se marca como `NOT_RUN`. No sustituye una auditoría completa de accesibilidad ni el criterio de diseño humano.
